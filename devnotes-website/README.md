# DevNotes website

A static website for deep, interview-focused tech notes. Notes are written in Markdown, a small
build script turns them into page data, and the `site/` folder is the finished website you upload.

No frameworks and no dependencies. You only need Node.js (16+) to rebuild after editing notes.

```
devnotes-website/
├── content/                      ← YOU EDIT THESE
│   ├── catalog.json              tracks + topics shown on the site (Java, Spring, …)
│   └── java/core-java/
│       ├── 01-oop-principles.md  one Markdown file per chapter
│       └── …
├── site/                         ← YOU UPLOAD THIS (the website)
│   ├── index.html
│   ├── assets/css/styles.css
│   ├── assets/js/app.js
│   └── data/                     generated by build.js (don't edit by hand)
├── build.js                      Markdown → site/data
└── serve.js                      local preview server
```

## Preview locally

```bash
npm run dev
```

Then open http://localhost:5173. (Pages use real paths now, so open the site through the preview
server — double-clicking `site/index.html` no longer works.)

## Site settings (`content/catalog.json` → `"site"`)

| Setting | What it does |
| --- | --- |
| `url` | Your live address, e.g. `https://devnotes.in` — used for canonical URLs, the sitemap and robots.txt |
| `contactEmail` | Shown on the Contact, Privacy and Terms pages (AdSense needs a way to contact you) |
| `adsenseClient` | Your AdSense publisher ID, e.g. `ca-pub-1234567890123456` — adds the AdSense script to every page and generates `ads.txt` |
| `googleSiteVerification` | The `content` value of Search Console's HTML-tag verification |
| `goatcounter` | Your GoatCounter site code (`lunarai` for `https://lunarai.goatcounter.com`) — adds cookie-free page-view analytics to every page, counts in-app page changes, and adds a GoatCounter paragraph to the Privacy Policy |
| `ogImage` | Optional 1200×630 PNG (e.g. `assets/img/og-image.png`) for link previews on WhatsApp, LinkedIn, X |
| `support` | UPI donation settings (UPI ID, payee name, suggested amounts, QR image) |

Run `npm run build` after changing any of them.

## What the build generates

`build.js` writes, into `site/`:

- `data/` — chapter data, search index and catalog for the app;
- a pre-rendered **`index.html` for every page** (`/java/collections/hashmap/` …) with the full chapter text,
  title, description, canonical URL and structured data, so Google and AdSense reviewers see real content;
- `sitemap.xml`, `robots.txt`, `404.html`, and `ads.txt` (once `adsenseClient` is set);
- static pages from `content/pages/*.md` — About, Contact, Privacy Policy, Terms & Disclaimer.

The page layout for all of these is `templates/page.html`.

## Upload / host

Upload the **contents of `site/`** to the **root of your domain**. There is no server code, but the host must
serve `/some/path/` from `/some/path/index.html` (all of the hosts below do this) and use `404.html` for missing pages.

| Host | How |
| --- | --- |
| **Firebase Hosting (Google)** | `npm i -g firebase-tools` → `firebase login` → `firebase init hosting` (keep the existing `firebase.json`, public dir `site`) → `firebase deploy`. Then Hosting → *Add custom domain* |
| **Netlify** | Drag the `site` folder onto app.netlify.com/drop |
| **Cloudflare Pages** | Create project → upload `site/` |
| **Vercel** | `vercel deploy site` |
| **cPanel / shared hosting** | Upload the contents of `site/` into `public_html` |

`firebase.json` already sets clean URLs, caching headers and a 301 redirect for the old Design Patterns URLs.
Old `/#/...` links from before the switch to real paths are redirected automatically by the app.

## Google Search Console and AdSense checklist

1. **Use your own domain** (e.g. `devnotes.in`) and set `site.url`. AdSense doesn't accept free subdomains like `*.web.app` or `*.netlify.app` as the site to review.
2. Set `site.contactEmail`, run `npm run build`, and deploy.
3. **Search Console** → add the domain → verify (DNS record, or HTML tag via `googleSiteVerification`) → *Sitemaps* → submit `https://your-domain/sitemap.xml`.
4. Wait until pages show as indexed (often 1–4 weeks).
5. **AdSense** → sign up with the site URL → copy your `ca-pub-…` ID into `site.adsenseClient` → build and deploy (adds the AdSense code and `ads.txt`) → click *Verify* / *Request review* in AdSense.
6. In AdSense → **Privacy & messaging**, turn on the **European regulations (GDPR) consent message** — Google requires a certified consent banner for visitors from the EEA, UK and Switzerland.
7. Review usually takes from a few days to a few weeks. Keep publishing in the meantime.

## Landing page and learning paths

The home page is a landing page with live stats (counted from your notes) and **Featured Learning Paths**.
Paths are defined in `content/catalog.json` under `"paths"`: each has a `name`, an `icon`
(`java`, `target` or `layers`) and `steps` (a list of `track/topic` ids). The progress bar fills as you
mark chapters read, and topics that are still "soon" show greyed out in the route.

## Edit a chapter

1. Edit the `.md` file in `content/java/core-java/`.
2. Run `npm run build` (or `node build.js`).
3. Re-upload `site/` (the chapter's `index.html` page and `site/data/` change).

## Add a new topic (e.g. Spring Boot)

1. Create a folder `content/<track-id>/<topic-id>/`, e.g. `content/spring/spring-boot/`.
2. Add chapters named `01-something.md`, `02-something-else.md`, … (the number sets the order; the rest becomes the URL).
3. In `content/catalog.json`, find the topic and set `"status": "live"` (add the track/topic if it is new).
4. Run `npm run build`.

The home page, sidebar, search and progress tracking pick it up automatically.

## Chapter format

Each chapter starts with front matter:

```markdown
---
title: Records (Java 16+)
subtitle: One-line description shown under the title and on cards.
order: 10
---
```

Then normal Markdown: `## Section` headings (these build the "On this page" menu), `### Sub-headings`,
paragraphs, `**bold**`, `` `code` ``, lists, tables and fenced code blocks.

### Special blocks

| Write this | You get |
| --- | --- |
| ` ```java ` | Highlighted code with a Copy button |
| ` ```output ` | Console output, attached under the previous code block |
| `> [!TIP]` / `[!NOTE]` / `[!WARNING]` / `[!IMPORTANT]` | Coloured callout box |
| `> [!QUESTION] Can X do Y?` + `> answer` | Inline interview-question card |
| ` ```flow ` | Vertical flow diagram, one box per line (` ```flow-h ` = horizontal, ` ```flow-up ` = upward arrows) |
| ` ```tree ` | Hierarchy diagram; indent children by 2 spaces |
| ` ```refs ` | Variable → object memory diagram: `e1, e2 -> Object A \| id = 101` |
| ` ```buckets ` | HashMap bucket diagram: `3: Employee(101)` |

Diagram details:

- Text after the fence name is the caption: ` ```flow HashMap internal flow `
- `Title | sub line | sub line` puts extra lines inside a box.
- `{sealed}` / `{final}` / `{new}` at the end of a box adds a badge.
- In `flow`, a line starting with `: ` labels the next arrow; a `---` line starts a new column.
- In `refs`, `emp = 0x100` shows a variable with its value.

### Tabs on the chapter page

- **Interview Q&A**: any `##` section whose title contains "Interview". Every `###` inside it becomes a
  collapsible question card (works with Practice mode, which hides answers).
- **Quick Revision**: sections titled "Quick Revision", "Cheat Sheet" or "Chapter Summary".
- **Examples**: sections that contain Java code.
- Sections titled "Common Mistakes" / "Best Practices" get ✕ / ✓ styled lists.

## Features

Search across all notes (`/` to focus) · dark/light theme · reading progress · "Mark as read" with
per-topic progress (saved in the visitor's browser) · section deep links · practice mode for
interview questions · mobile layout with slide-out menu · print-friendly chapters.
